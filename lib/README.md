# lib

What the [hooks](../hooks/README.md) and the [scripts](../scripts/README.md) call but the harness never invokes directly.

## Shared readers

| File | Role |
|------|------|
| `platform.sh` | sourced first by every hook, `bin/cctoolkit`, the tools and the shell scripts: nothing on macOS and Linux; under Git Bash on Windows, `python3` resolved to an interpreter that runs (cached in `/tmp/cctoolkit-python`), `jq -b`, Python in UTF-8 mode writing LF (`windows/sitecustomize.py` on `PYTHONPATH`), and `kit_path VAR`, which rewrites a path in place to `C:/x/repo` form. `CLAUDE_PROJECT_DIR` and `CLAUDE_PLUGIN_ROOT` are rewritten on load. A hook reached through a backslashed path cannot find it: each hook's first `case` line reruns it from the `/` form |
| `project-root.sh` | the repo the kit serves: `$CLAUDE_PROJECT_DIR`, else the git top level of the working directory — never the kit's own location |
| `kit_config.py` | `kit.config.json` resolved over its preset — the one reader every hook and script goes through ([`presets/README.md`](../presets/README.md)); `root_of(path)` the repo a hook judges a path in — the linked worktree of the checkout holding it (`worktree_of`, read off its `.git` file, no git call), else `project_root()`; `main_worktree(root)` the checkout a worktree belongs to |
| `knowledge.py` | the knowledge base's one parser: objects by their id heading, `kit:handlers`, `kit:observed`, the spec's delta anchors, `HISTORY.md` rows and sync marks, the largest id used, the rules outside their place (`misplaced`, for `knowledge-write` and `knowledge-merge`); `guarded <path>`, for `bounds_knowledge_guarded` in `bounds-common.sh`: a context's `rules.md`, `decisions.md` or `HISTORY.md` |
| `knowledge_index.py` | the derived index under `<root>/.index/` and `INDEX.md`, for `knowledge-index`, `knowledge-write` and `ask`: per-file parse kept while the file's stamp or digest holds, fields that cross files recomputed in memory |
| `kit_testtag.py` | the `testTag` adapters: xUnit, pytest, JUnit, Jest |
| `rule_sheet.py` | a rule sheet's sections (anchor, else exact folded title) and its `kit:rules` table, the fixed shape — read by `handler-claude-md-check.sh` and `rules-coverage` |
| `tdd_scope.py` | for `hooks/tdd-scope-guard.sh`, `guard-tdd-scope.sh` and `cctoolkit tdd-scope`: the RED/GREEN write check: snapshot per agent, write log, tree comparison, RED rerun against `tdd.stubFailure` (the last `commands.test` or `commands.testFast` run), restore; a `tdd-cycle` agent's RED checkpoint (author checks, contract methods, new snapshot, implementer from then on); state under `work_file.tmp_dir("tdd-scope")` |
| `closing_level.py` | for `sheet-cycles --index` (the files the block plans) and `cctoolkit closing-level` (the batch diff): the run-lot closing level, `full` when the block forces it, a file matches a `closing.full` rule for its change kind, the production files pass `closing.maxProductionFiles` or a cycle has a ripple — the last two lifted by a block asking `light`, a rule never; `light` otherwise, each level with its reasons |
| `pane_file.py` | for `run_notes.py`, `run-validate`: the pane file `run/.pane.jsonl`, written whole by the `run-lot-pane` mod alone (notes, answers to `## To validate`), answered by `ack` lines of the work file |
| `run_notes.py` | for `hooks/run-notes.sh`: the batch and work file an agent works for, read once from the first line of its run-lot prompt and cached per agent; each note of that batch it has not received, as additional context, then an `ack` naming the agent |
| `work_file.py` | the run work file `run/.work.jsonl` of run-lot and run-plan — shared by the two batches of a parallel run, the worktree's included: one JSON line per event, appended and rewritten under `flock`; read by `batch-baseline`, `run-work`, `run-question`, `sheet-cycles`, `plan-next-batch`, `pre-audit` |

## Modules

| File | Called by | Role |
|------|-----------|------|
| `guard-git.sh` | `bash-dispatch.sh` | forbids mutating Git commands (`add`, `commit`, `push`), including through `rtk git`, `git -C`, `cd && git`. Reading stays free; `add -N` and `apply` fall through to `ask` for the worktree hand-back |
| `guard-cat-bounds.sh` | `bash-dispatch.sh` | denies a bare `cat`, `head` or `tail` on a file past 120 lines (`CLAUDE_READ_BOUNDS_THRESHOLD`) or 8 kB (`CLAUDE_CAT_BOUNDS_BYTES`) — 400 lines or 24 kB in a subagent since 2026-10-09, the bar `read-bounds.sh` applies — the byte trigger catches Markdown that wraps at the paragraph, where a line count alone waves an 18 kB report through. `read-bounds.sh` is a `PreToolUse:Read` hook and has no reach over Bash; measured on one .NET batch, `Read` fell to 1 % of the context fill while Bash rose to 85 %. `head`/`tail` count for the span they ask for: `head -20 f` passes, `head -n 5000 f` or `tail -n +1 f` is a dump in disguise. The sed and awk forms that print a file count as the cat, head or tail they amount to: `sed -n 'A,Bp'` for its span, `sed Nq` as a head, any other `sed` without `-n` and `awk 1` or `awk '{print $0}'` as a whole file; `sed -i` and a pattern filter pass. `2>&1`, `2>/dev/null` and `>&2` leave the output in the context and are no redirect. Never fires on a pipe, a stdout redirect, a binary format, or a second identical command from the same agent. In the knowledge base, a whole dump of a context's `rules.md`, `decisions.md` or `HISTORY.md` is denied whatever its size and sent to `cctoolkit ask`, as `read-bounds.sh` does for a `Read` — `head -20` of it passes, `knowledge-extractor` is exempt |
| `guard-diff-bounds.sh` | `bash-dispatch.sh` | denies `git diff`, `git show` and `git log -p` when nothing bounds the output and the patch passes 400 changed lines (`CLAUDE_DIFF_BOUNDS_LINES`). Added 2026-09-17, after a 14-day measurement: `rtk` compresses the dotnet side well — `dotnet build` -59.5 % over 1 295 calls, `dotnet test` -95 to -100 % — but not a patch, and a bare `git diff` on a working tree of the day was 109 kB, ~27 k tokens carried to the end of the session. The size is measured, not guessed: the same command is re-run with `--numstat`, so a three-line diff is never refused, at the price of a second git call (~50 ms). `LC_ALL=C` on that sum — BSD awk aborts on the first invalid byte sequence of a binary or latin-1 file, and an empty sum used to read as a small patch. `--stat`, `--numstat`, `--shortstat`, `--name-only`, `--name-status`, `--quiet`, a pipe, a redirect and a second identical command from the same agent all pass |
| `bounds-common.sh` | sourced by `read-bounds.sh` and `guard-cat-bounds.sh` | the shared body of the two bound guards: thresholds, the binary and instruction-file skip lists, the per-language outline, and the refusal layout. Extracted 2026-09-11 from ~45 lines duplicated between them — the outline block was identical down to the regexes, differing only in the variable holding the path. Cost was never the point, divergence was, and it had already happened: `guard-cat-bounds` skipped `.zip` and `.nupkg` where `read-bounds` did not, so a `cat` of a package passed while a `Read` of it was denied and handed a text outline of a binary. Callers keep only what genuinely differs: the tool named in the refusal and the two sentences telling the caller how to read a range and how to force. Also the knowledge base's guard: a context's `rules.md`, `decisions.md` and `HISTORY.md` are refused whole whatever their size and sent to `cctoolkit ask` (`bounds_knowledge_guarded`, the refusal in `bounds_knowledge_reason`), `knowledge-extractor` exempt — it rewrites them in its staging; the basename filters first, so python3 runs for those three names only |
| `guard-integration-filter.sh` | `bash-dispatch.sh` | denies a `dotnet test` on the `IntegrationTests` project, or a direct run of its test assembly (`commands.testFast`), carrying neither `--filter-class` nor `--filter-method`, subagents included — a whole run was measured at 602 s, twice, where the impacted context fits in one filtered minute. `rtk`, `cd &&`, env assignments and redirections pass; only the project and the presence of a filter are inspected |
| `guard-tdd-scope.sh` | `bash-dispatch.sh` | for the TDD agents only (`agent_type` ending in `tdd-implementer`, `tdd-test-author` or `tdd-cycle`): adds the agent id to a `tdd-cycle` agent's `cctoolkit tdd-scope red` (an `updatedInput`); denies a write through Bash under a source or test root — redirection, `tee`, `sed -i`, `rm`/`mv`/`cp`, `git checkout`/`restore`/`stash`, a formatter, inline interpreter code, a write call in the code an interpreter reads from a heredoc (`python - <<'E'`, wherever it points: after a `cd` its paths are relative); any other heredoc body is data — and logs the test command for the RED rerun (`tdd_scope.py`) |
| `guard-auditor.sh` | `bash-dispatch.sh` | for the batch auditor only (`agent_type` ending in `ddd-tdd-auditor`): denies `run_in_background`, a recursive `grep` (`git grep` skips build output: 121 s measured against 3 s), and a test command on a suite of the newest `suites-green` marker while no file of the source or test roots changed after it — `audit-capture --suites-green` writes the marker, an audit fix makes it stale. No marker never denies |
| `rewrite-piped-filter.sh` | `bash-dispatch.sh` | appends a local stdout filter to a command RTK cannot shrink, one profile per filter. `graphify-query` pipes a bare `graphify query` through `graphify-query-filter.sh`, which drops sourceless nodes and `community=X` and collapses `[src=PATH loc=LNN]` to the clickable `PATH:NN` — measured -14 to -30 % across two .NET repos, every source-carrying node preserved; `explain` is left alone, a few hundred bytes with nothing to trim. `git-grep` pipes `git grep` through `git-grep-filter.sh`, which turns the repeated path into a per-file header — lossless, rebuilding `path:NN:content` from the grouped form diffs byte-identical against the raw output, and the gain follows path length against content length (-32 to -48 % on a .NET tree with ~130-character paths, -6 % on this repo). Both fire only when the LAST segment of the command is the bare match, so `cd x && graphify query "y"` counts; any pipe, redirect or substitution leaves the command alone, which is the escape hatch. Merged 2026-09-11 from `rewrite-graphify.sh` and `rewrite-git-grep.sh`: the two differed only by a trigger regex and a filter path |
| `graphify-query-filter.sh` | piped by `rewrite-piped-filter.sh` (profile `graphify-query`) | stdout filter of `graphify query`: drops sourceless nodes and `community=X`, collapses `[src=PATH loc=LNN]` to `PATH:NN` |
| `git-grep-filter.sh` | piped by `rewrite-piped-filter.sh` (profile `git-grep`) | stdout filter of `git grep`: one header per file instead of the repeated path, lossless |
| `rewrite-rtk.sh` | `bash-dispatch.sh` | strips the `/usr/bin/`, `/bin/`, `/usr/local/bin/` prefix off `grep`/`rg`/`find`/`egrep`/`fgrep`, prefixes `dotnet test\|restore\|format` with `rtk` in command position (`rtk hook claude` only rewrites `dotnet build`, though the `rtk dotnet` filter accepts all four), every rewrite in command position and none in a heredoc, then pipes the payload to `rtk hook claude` itself. When rtk answers nothing on a command the module rewrote, the module emits the `updatedInput` itself, without a `permissionDecision`: the user's rules judge the rewritten command, so a `dotnet test; rm …` is never approved past them (until 2.5.0 it carried an `allow`). In a linked git worktree (a `.git` file above the payload's `cwd`) a command running git is left whole: Claude Code's worktree isolation refuses `rtk git`. Without `rtk` on the PATH the module does nothing. The kit *is* the RTK rewrite plus the normalisation — a repo installing it needs no global `rtk init -g` |
| `batching-nudge.sh` | `bash-dispatch.sh` | appends one line of `additionalContext` when the last 6 tool-carrying turns each held a single call (`CLAUDE_BATCHING_WINDOW`), once per session since 2026-10-09 — 16 % of turns batched after a reminder against 12 % without, over 609 reminders. Never denies, never rewrites. Wired on Bash but reads the transcript, so it counts every tool. Main chain only: a subagent drops its context after ~30 turns, where the same run costs 32x less |
| `graphify-freshness.sh` | autosync + statusline | counts the sources newer than `graph.json`, 20 s TTL cache |
| `context-report.sh` | `cctoolkit context-report`, by hand | reads the context log back: heaviest files, tokens per load reason. `--session` narrows it to the last session |

A module reads `HOOK_CMD` / `HOOK_INPUT` / `HOOK_SESSION_ID` / `HOOK_AGENT_ID` / `HOOK_AGENT_TYPE` / `HOOK_BACKGROUND` / `HOOK_TRANSCRIPT_PATH` from the environment instead of stdin: `HOOK_CMD='ls' bash lib/<name>.sh`.

## RTK gotchas (verified on rtk 0.42.4)

- **`rtk gain` prints `[warn] No hook installed` even when this hook is active**, and `rtk init --show` prints `[--] Hook: not found`. Both detectors only inspect `~/.claude/settings.json`; a hook declared in a project's settings or a plugin's `hooks.json` is invisible to them. Trust the rewrite, not the warning — `echo '{"tool_name":"Bash","tool_input":{"command":"grep -rn foo src"}}' | rtk hook claude` must answer with an `updatedInput` carrying `rtk grep`.
- **The absolute-path bypass is real**, which is what the normalisation buys: fed `/usr/bin/grep -rn foo src`, `rtk hook claude` returns nothing at all, where the bare `grep` gets rewritten.
- **`rtk hook claude` is idempotent** — `rtk git status` comes back unrewritten, so a global RTK hook (`rtk init -g --auto-patch`) and this one never produce `rtk rtk git status`. **Register only one of them anyway.** Both fire on the same `tool_input`, and on a symbol-discovery `grep` the global one answers `rtk grep …` while the dispatcher answers `graphify explain "X"` — two competing `updatedInput` with no defined winner. The dispatcher already performs the RTK rewrite: drop the global hook.
- **Still bypassing**: the `command` builtin. `command grep …` is not stripped by the normalisation.
- `rtk grep` answers with a match count, not the matching lines. Repo-wide it pays; on a single short file it costs a turn to re-read with `awk`.
