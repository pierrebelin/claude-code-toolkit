# Hooks

Wired in `hooks.json`, every command written `bash "${CLAUDE_PLUGIN_ROOT}/hooks/x.sh"`. The modules these hooks call live in [`lib/`](../lib/README.md).

| Hook | Event | Role | Blocking |
|------|-------|------|----------|
| `bash-dispatch.sh` | `PreToolUse:Bash` | single entry point: parses the payload once, then runs `lib/guard-git.sh`, `lib/guard-tdd-scope.sh`, `lib/guard-cat-bounds.sh`, `lib/guard-diff-bounds.sh`, `lib/guard-integration-filter.sh`, `lib/guard-auditor.sh`, `lib/rewrite-piped-filter.sh` and `lib/rewrite-rtk.sh` in that order. Each `MODULES` entry carries its filter — a regex on the command or on `agent_type` — tested before the module is forked: a module whose filter fails costs nothing (a fork is ~20 ms on Windows). First module that answers wins, so a rewrite is never rewrapped by the RTK rewrite; the two output filters sit before the RTK rewrite because `rtk hook claude` has no rewrite of its own for `graphify` or `git grep`. `lib/batching-nudge.sh` runs outside that chain, on the main chain with a transcript only: it decides nothing, and its advice is grafted onto whatever the chain answers | depends on the module |
| `explore-guard.sh` | `PreToolUse:Agent` | delegation guard, two checks in cost order: every `Agent` call carries a `description`; the model is chosen rather than inherited — explicit on `Explore` and `general-purpose`, `haiku` by default but never forced (required on `Explore` until 2026-10-09). Since 2026-09-17 the check reaches every spawn: a call with no `subagent_type` is read as `general-purpose` — it used to fall through the type filter and inherit Opus, which is where the mechanical refactors were billed — and a custom agent is asked for a model unless its own file pins `model:` in frontmatter. A `fork` passes untouched: it runs on the caller's model whatever the parameter, and carries the caller's context. When both pass it appends the report contract to `tool_input.prompt` (caveman-ultra, 20-line cap, 40 for `Plan`; a prompt stating its own size — `60 lines max` — keeps it): `additionalContext` would land in the caller's context, only the prompt reaches the agent. Own hook: a spawn costs ~55k startup tokens, a grep ~300, and the agent's final report is re-injected whole into the caller | yes |
| `implement-tdd-guard.sh` | `UserPromptSubmit` + `PreToolUse:Skill` | denies a second `/implement-tdd` launch in a session that already closed a batch — it reads the transcript for the closing literal of the skill (French and English wordings both matched). Correction mode passes. Re-issuing the identical launch passes through; the chained batch would otherwise pay the whole accumulated context of the previous one, measured at 1.9x the input at equal request count. Also denies a launch at effort `high`, `xhigh` or `max`, reading the level the statusline dropped in `$TMPDIR`: the orchestrator runs 100 to 180 turns at 8.6 s each there, and only `/effort` can change it. Inside a subagent it reads the agent's own transcript (`<session>/subagents/agent-<id>.jsonl` beside the payload's, which is the main chain's), so a batch the main chain closed never refuses a subagent | yes, once per closed batch and once per launch at too high an effort |
| `read-bounds.sh` | `PreToolUse:Read` | denies a `Read` with no `offset`/`limit` on a file past 120 lines or 8 kB (`CLAUDE_READ_BOUNDS_THRESHOLD`, `CLAUDE_CAT_BOUNDS_BYTES`) — 400 lines or 24 kB in a subagent since 2026-10-09 (`CLAUDE_READ_BOUNDS_SUBAGENT_THRESHOLD`, `CLAUDE_READ_BOUNDS_SUBAGENT_BYTES`) — and records the denial per agent. Re-issuing the identical `Read` passes through — that is how a full read is forced; the pass applies to the agent that asked for it, not to its siblings or its parent. Skips images, PDFs and notebooks. A numeric `offset` or `limit` leaves at a regex on stdin, before `lib/platform.sh` and jq. A context's `rules.md`, `decisions.md` and `HISTORY.md` in the knowledge base are denied a whole `Read` whatever their size: [`lib/README.md`](../lib/README.md) § `bounds-common.sh`. | yes, once per file and agent |
| `handler-claude-md-check.sh` | `PostToolUse:Edit\|Write` | cross-checks the rules table (`kit:rules`) of the rule sheets (`layout.useCase`, `layout.ruleSheet`) against the tags the tests carry (`testTag` adapter); reports untested rules and orphan tests. A sheet with no anchors is read by its exact English or French titles (`Business rules` / `Règles métier`, `Flow` / `Flux`, `Emitted events` / `Événements émis`, accents and case folded) and its header row (`ID`, `Rule` / `Règle`, `Exception / Outcome` / `Résultat`). Speaks through `hookSpecificOutput.additionalContext`: on `PostToolUse`, plain stdout at exit 0 reaches the transcript only, never the model — 231 reports went unread that way before 2026-09-13. A file outside every use-case and test root leaves in bash, per the scope cache (`lib/scope-cache.sh`) | no, warning only |
| `knowledge-reminder.sh` | `PostToolUse:Edit\|Write` | after the main chain edits a file of a use-case folder, or an aggregate (`layout.aggregate`), while a knowledge base exists: one line naming the use case it falls in (or a new one) — for an aggregate, the use cases whose handlers name it — and `/cctoolkit:knowledge-sync <Context>` — the line of `knowledge-scan --reminder`, the one the optional pre-commit hook prints. A batch keeps the base aligned through its plan's merge; a hotfix in the main session does not. Subagents skipped before `lib/platform.sh`, once per file and session (`/tmp/claude-knowledge-seen-<session>`), through `additionalContext`. A repo without a knowledge base, or a file outside the use-case roots and the aggregates, leaves in bash, per the scope cache (`lib/scope-cache.sh`) | no, warning only |
| `graphify-autosync.sh` | `Stop` | rebuilds the graph if the working tree moved. `mkdir` lock, anti-shrink guard (auto `--force` if the drop is ≤ 2 %) | no |
| `tdd-scope-guard.sh` | `SubagentStart` + `PreToolUse:Edit\|Write` + `PreToolUse:StructuredOutput` | what the TDD agents write, checked on the tree, never on their report (`lib/tdd_scope.py`): a snapshot at start; a `tdd-cycle` agent is an author until its RED checkpoint (`cctoolkit tdd-scope red`: the RED checks below, then a new snapshot), an implementer after it, and its structured output must carry the checkpointed `red` unchanged; every write logged per agent; at the structured output, the tree since the snapshot minus what other agents wrote — at GREEN never refused: each changed test file is a `test-edit` line of the run work file its prompt names (`evidence.jsonl` without one), its `tdd.assertion` lines removed and added, judged by the audit; at RED a changed source file absent from `stubs`, an `ALREADY_GREEN` whose `pendingRipple` is not the cycle's `sheet-cycles --pending` list (cycle and work file read off its prompt), a RED test failing on the stub when its command is rerun — refused with the exact reason the agent restores, fixes, or carries as the `diagnostic` of a `BLOCKED`. Every other agent leaves at a string match. `timeout` 300 on `StructuredOutput` (the rerun) | yes |
| `run-notes.sh` | `PostToolUse` (every tool) | a note the user leaves for a batch in the `run-lot-pane` mod (`run/.pane.jsonl`) reaches each agent of that batch at its next tool call, once (`lib/run_notes.py`); the main thread leaves at a string match, an agent outside a run at its cached state, its session and agent ids read by a bash regex (jq when the payload holds either key twice), python runs only while the pane file holds a note | no |
| `subagent-report-shape.sh` | `SubagentStop` | checks the SHAPE of a `## RED` / `## GREEN` report — required lines, observed exit code on the `Command` line, `| Test | Case covered |` table — and blocks with a reason so the agent re-emits a complete report from the context it still holds, instead of costing the orchestrator a turn plus a `SendMessage` (1 to 4 per batch). Form only: a non-empty diff or an unexpected exit code is the orchestrator's call, never the agent's. `stop_hook_active` closes the loop; `## BLOCKED` and every other agent pass untouched | yes, once per malformed report |
| `worktree-graphify-link.sh` | `SessionStart` | symlinks the main working tree's `graphify-out/` into a linked worktree. graphify resolves its graph only at `<cwd>/graphify-out/graph.json` — no parent lookup, no env var — so `query`, `explain`, `path` and `affected` all fail in a worktree without it. No-op outside a linked worktree | no |
| `session-cleanup.sh` | `SessionStart` | drops this session's per-session state under `/tmp` — read-denial memories, once-per-session markers (glob, subagents included) —, purges what is older than two days | no |
| `windows-env.sh` | `SessionStart` | Windows only: appends one line sourcing `lib/platform.sh` to `$CLAUDE_ENV_FILE`, so the Bash tool's commands get the same `python3`, `jq` and Python as the hooks. Exits at once elsewhere | no |
| `context-log.sh` | `InstructionsLoaded` | logs every instruction file entering the context (path, bytes, ~tokens, load reason) into `.claude/context-log.tsv` | no, observes only |
| `clear-nudge.sh` | `UserPromptSubmit` | reads the last assistant `usage` in the transcript and, at every 150k-token step of replayed context (`CLAUDE_CLEAR_NUDGE_STEP`), appends one line of `additionalContext` asking the model to tell the user that `/clear` is due if the phase is done. A context back under a step (a `/compact`, which keeps the session id) re-arms it | no |

A hook on a hot event (`PostToolUse` of every tool, `Edit|Write`, `SubagentStart`) may read stdin and leave on a plain string match before sourcing `lib/platform.sh`, the Windows rerun line still first: `run-notes.sh`, `tdd-scope-guard.sh`, `knowledge-reminder.sh` and `handler-claude-md-check.sh` do. Nothing before the source may call `kit_path`, `python3` or `jq` — the functions it defines on Windows.

`tools/doctor` also runs on `SessionStart` (`--quiet`): see [`tools/README.md`](../tools/README.md).

## Dependencies

What each tool is used for and what is lost without it: [`INSTALL.md`](../INSTALL.md#dependencies).

Every hook exits 0 when its dependency is missing, except `lib/guard-git.sh`, `explore-guard.sh`, `read-bounds.sh` and `implement-tdd-guard.sh` which block by design. Removing the `graphify-*` scripts and `read-bounds.sh` from `hooks.json` (in a fork) leaves a coherent kit; `bash-dispatch.sh` keeps working with any subset of its modules present.

## Adapting

| File | What to change |
|------|----------------|
| `lib/graphify-freshness.sh` | scanned dirs and extensions: indexed languages and folders |
| `lib/guard-integration-filter.sh` | `dotnet test`, `IntegrationTests`: the slow suite and its filter flags — inert on another stack |

Every hook and script resolves the repo through `lib/project-root.sh` / `kit_config.project_root()` — `$CLAUDE_PROJECT_DIR`, else the git top level of the working directory — never from its own location. The `graphify-*` scripts accept `GRAPHIFY_REPO` to target another checkout.

A hook judging a path follows the tree it lies in: a batch run beside another works in a linked worktree of the checkout (`cctoolkit batch-worktree`, `run.parallelBatches`) while `$CLAUDE_PROJECT_DIR` stays the checkout. `tdd-scope-guard.sh` (`lib/tdd_scope.py`) moves an agent's snapshot to that worktree on its first Edit or Write there, or its first Bash call opening with `cd <worktree> &&`, and checks that tree from then on; `handler-claude-md-check.sh` and the knowledge-base guard of `read-bounds.sh` load the worktree's config for a file under it (`kit_config.root_of`); `lib/guard-auditor.sh` reads the worktree's `suites-green` marker for a call opening with `cd <worktree> &&`. Only a linked worktree of the checkout's own repository is followed: any other path is judged as before.

A hook change comes with a case in [`evals/`](../evals/README.md).
