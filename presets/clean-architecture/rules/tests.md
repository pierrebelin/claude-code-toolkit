# Testing rules

xUnit v3 / Microsoft Testing Platform. Assertions: **xUnit built-in only** — no FluentAssertions.

## Suites

| Suite | Scope |
|-------|-------|
| `CoreTests` | Shared library, not a suite: hand-written mocks (`Doubles/`, no Moq/NSubstitute) + fluent builders (`DataBuilder/`), fixtures, assets |
| `UnitTests` | Handlers (Domain exercised through them) on in-memory mocks, fixture builder pattern |
| `IntegrationTests` | SQL Server Testcontainers — needs Docker |
| `ContractTests` | `WebApplicationFactory` + Verify snapshots |
| `ScriptingTests` | DSL parser, templates, presets |
| `E2ETests` | Business lifecycle over ≥2 operations, Aspire-driven |
| `ArchitectureTests` | ArchUnitNET (layer deps, naming) — no cross-layer leaks, Domain depends on nothing, API contracts in `Abstractions`, no leaked internals |

## What is tested

Target = **observable business behaviour** via public API, tied to a business rule. Never private helper or internal detail.

Domain class, value object included, never tested directly (`PriceConstraintTests`) — always via use case or service (`ValidateDiagramTests`). Aggregate method exercised via its handler.

## Assertions on shared conventions

Assert the value the shared code produces, never the raw input. A helper that normalizes what it receives (error parameters, a serializer, a formatter) changes its shape: compare against the normalized form, never against the typed value. Before asserting an output shaped by a shared helper, read the helper.

A registry that grows batch after batch (catalog, inventory, mapping) is never asserted by a hand-written count or a hand-maintained list: derive the expectation (reflection over the declaring types) and pin a few anchors by name.

Fixture ids are fixed once in the constructor, never regenerated by a `With…` step: a detail built earlier keeps the id it was given.

## Traceability

Handler test declares its rule **on itself**, with `Trait`:

```csharp
[Fact]
[Trait("RM", "GetProduct/RL-02")]
public async Task ShouldThrowNotFound_WhenProductBelongsToAnotherOrganization()
```

Value: `{HandlerFolder}/{RM|RL-xx}` — handler folder name under `src/{{PRODUCT}}.Application/**/`, then row id in its rules table (`kit:rules`). Prefix = **handler folder**, not aggregate: one `RM` id (numbered per aggregate) appears in every handler that applies the rule, so the folder tells which handler the test proves. Test covering two rules carries two attributes. Trait read in any suite, carried by unit and integration tests: an integration test proving a documented rule covers it as a unit test does.

`handler-claude-md-check.sh` reports, on every edit of handler or handler test: rules with no trait, traits citing rule absent from table, tests with no trait in a class carrying some. Warning only, never blocking. Only `UnitTests` bind every test. `ContractTests` and E2E tests carry no trait: a contract test freezes the HTTP shape of a route, an E2E test proves a journey; the rule behind either is proven by the handler test. `IntegrationTests` bind those covering a documented rule.

Tests outside handler folders (`Core/`, `ScriptingTests`) out of scope — no rule to bind. No `Aggregates/` or `ValueObjects/` test folder: domain classes are covered through handlers.

## Naming

Test method: `Should{Result}_When{Condition}`, `{Result}` = **actual assertion**, not intent. Exception: contract tests, one happy path per route, are named `Should{Action}()` (`ShouldCreateOrder()`).

| Suite | Class pattern | Example |
|-------|---------------|---------|
| UnitTests, ContractTests | `{Feature}Tests` / `{Feature}Fixture` | `UpdateDiagramNodeTests` |
| IntegrationTests | `{MethodName}Tests` / `{MethodName}Fixture` — no repository-name prefix | `GetByOrganizationTests` |
| E2ETests | `{Feature}LifecycleTests` | `ProductLifecycleTests` |
| Mocks (CoreTests) | `Mock{Interface}` | `MockModuleDiagramRepository` |
