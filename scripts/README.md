# scripts

Repo-wide scanners and one-shots — never a hook: a hook fires per edit, a scan reads the whole repo. Every script needs `python3`.

## `bin/cctoolkit`

On the Bash tool's `PATH` while the plugin is enabled. `cctoolkit <script>` runs `scripts/<script>`, `cctoolkit doctor` and `cctoolkit bulk-read` the [tools](../tools/README.md), `cctoolkit context-report` `lib/context-report.sh`, `cctoolkit config` `lib/kit_config.py` (`validate`, `command`, `scope-cache`), `cctoolkit evals` the [evals](../evals/README.md), `cctoolkit list` every command, `cctoolkit root` the plugin directory. Skills, agents and references call scripts only through it, never by path.

## Scripts

| Command | Role |
|---------|------|
| `detect-stack` | stack, test framework, product, and how many use-case folders each preset recognises — the model-free half of `/cctoolkit:kit-init` |
| `rules-coverage` | rules ↔ tags, repo-wide (a rule sheet without anchors is read by its `Business rules` / `Règles métier` title); `--ids <sheet>` lists the DDD/APP/PERF ids the sheet never cites; `--json` for the quality report |
| `untagged-tests` | tests carrying no rule tag; `--json`: counts per category and suite |
| `knowledge-scan` | read only: per bounded context, what `/cctoolkit:knowledge-sync` has to look at — `bootstrap` inventory when the base lacks the context, `incremental` packet since its sync marks (`sync <commit>` rows of `HISTORY.md` that are ancestors of `HEAD`, plus the working tree; commits carrying `Kit-Batch:` or adding a sync row skipped as covered; each file routed to its use cases with its diff, whitespace, import and comment lines dropped; pure renames and deletions of handlers `mechanical`), `full` when no mark is known any more. `--context`, `--since <commit>`, `--full`, `--json` for the extraction agent. `--reminder [--staged \| <path>…]`: the one line naming the use cases a change touches, printed by the pre-commit hook and `hooks/knowledge-reminder.sh`, always exit 0 |
| `knowledge-write` | the one writer of the knowledge base: drafts staged under `<root>/.sync/<Context>/` (laid out as the base, an ADR under the `adr/` of the context drafting it; an empty file deletes) with provisional ids (`CAT-RM-?1`) — `init` (the staging, and the base's own `.gitignore` — `.index/`, `.sync/`, `.merge/` — and `.gitattributes` — `*/HISTORY.md merge=union` —, both committed with the base), `status`, `validate --accept/--drop/--keep`, `rename`, `retire`, `apply [--context]` (the drafts of the contexts named: ids numbered, files written, one `sync <HEAD>` row with its delta per context, an ADR in its own context's only; refused on a dangling citation, a duplicate id or an unknown prefix), `mark` (the row alone, delta `—`); both rebuild the index and `INDEX.md`; `status\|apply --merge <CODE>` the same on a feature's merge staged under `<root>/.merge/<CODE>/`, its row's feature the spec's code. `apply` refuses a rule a draft leaves in a use case's file while several use cases apply it |
| `knowledge-merge` | the mechanical part of a delivered feature's merge into the knowledge base: `prepare <plan> [--partial]` (every batch ✅ DONE, or the objects whose batches are; collisions with the base, with the next free id; the spec's decisions and the sheets' ADRs drafted; the packet `knowledge-merger` works from), `stage <plan>` (the drafts assembled over the base, refused on a missing or unannounced draft, a dead citation, a misplaced rule, an `OVERVIEW.md` over budget; `+n −n` per file), `renumber <plan> <old> <new>` (an id rewritten in the plan folder and the source and test roots after a collision) |
| `knowledge-index` | the knowledge base's index: `<root>/.index/knowledge.jsonl`, one row per object (kind, context, status, `path:line`, citations, the use cases and handlers it reaches), git-ignored and incremental — a file is parsed again only when its stamp and digest moved — and `INDEX.md`, written when it differs; `--check` writes nothing, exit 1 and `INDEX.md stale` when the committed one lags — `doctor` and the `--pre-commit` hook run it. `knowledge-write apply` and `mark` run it |
| `ask` | the questions to the knowledge base: `"<question>"` ranked cards (BM25 over title, text, id and handlers; an id written in the question first; `--context`, `--kind`), `--id` objects whole with what they apply to and what cites them — a retired id, its `HISTORY.md` row —, `--handler` the use case and the rules binding it, `--context` alone the context's summary, `--history`. Every answer ends with `shown N of M` under `knowledge.askBudget`. Refreshes `.index/` itself, never `INDEX.md` |
| `next-id` | `<Context\|PREFIX> CU\|RM\|D` or `ADR`, `--count N`: the next free ids of the knowledge base, one above the largest found under `knowledge.root` (`HISTORY.md` included) and `todo/` — never given twice |
| `quality-report-check` | checks a `docs/metrics/quality-report-*` pair: arithmetic, evidence statuses (`measured`, `not_configured`, `skipped`, `missing`: a block not measured holds no number, a measured one belongs to the report commit), hotspot counts, the `codebase.*` blocks of `audit-collect` and `risk-cross` |
| `audit-worktree` | the quality report's throwaway worktree: `create` (detached at the main branch's commit, in the system temp, the untracked kit config copied, leftovers pruned first), `remove`, `prune` |
| `audit-collect` | the quality report's model-free measures in one JSON: `hotspots`, `rules-coverage` + `untagged-tests` as one traceability block, suppressions counted at the commit, dependency vulnerabilities (`dotnet list package --vulnerable` / `npm audit`), `access-cost --all`; each block `{status, reason, commit}`, `missing` rather than a guess |
| `risk-cross` | Danger Zone × per-file coverage (SonarQube generic, Cobertura or lcov) × Stryker survivors (`mutation-report.json`), for §7; a side not measured stays `null` |
| `report-assemble` | merges the audit's fragments into the report JSON: later wins, `tests.total` summed, an unknown first-level key refused |
| `bg` | detached jobs a Workflow agent waits for in bounded calls: `start <name> -- <cmd>`, `wait <name> --seconds N` (0 done, 1 failed, 3 running), `status`, `stop`, `log` — Stryker and SonarQube outlast a Bash call |
| `hotspots` | churn × complexity per source file (`layout.sources`), renames followed, creations, pure renames, merges and `.git-blame-ignore-revs` left out, ranked over a window ending at the commit date (`--days`, 365) with the whole history beside it, `fix:` commits counted; cyclomatic complexity by lizard, `missing` without it; Danger Zone ranked on the total complexity, then on the worst function — Markdown, or `--json` for `activity.hotspots` of the quality report |
| `audit-capture` | the deterministic audit material in one file, so `/verify-ddd-tdd` opens it once; `--base <work>` (the run work file) limits the diff to the batch's own files; `--suites-green <S1,S2>` writes the `suites-green` marker beside the output, read by `lib/guard-auditor.sh`; ends with the `## Mechanical audit — F<n>` table (`Axis \| Check \| Result \| Evidence`, `Result` `ok` / `gap` / `not checked`): only what the capture ran itself — `git diff --check`, files outside the batch, ids classified, cycles' final state and sheet methods on disk, test files a GREEN changed (the work file's `test-edit` lines: an assertion line removed is `gap`), access cost, build, `ArchitectureTests`, `--suites-green` — and the layer rules, always `not checked` |
| `pre-audit` | the mechanical gate before `/verify-ddd-tdd` — red means no fork. Gate 4 fails an unbound test only when the batch adds it (an older one in a touched class is listed with `·`), and only lists the trait check when the repo git-ignores `layout.ruleSheet`. Gate 8 (opt-in, `layout.sources.languageGuard`) lists French sentences added to production literals; gate 9 (opt-in, `layout.integrationGuard`) asks for a changed integration test or a waiver when persistence code changes |
| `access-cost` | awaited Infrastructure calls read off the syntax tree with ast-grep; C# only; `--base <work> FX` flags only the lines the batch added against `HEAD`; `--all --json` scans every source file for the quality report |
| `install-git-hooks` | links `settings.local.json` into new worktrees, for a plugin enabled at local scope; `--pre-commit`, opt-in: a reminder at each commit that the knowledge base may lag behind the staged handlers (`knowledge-scan --reminder --staged`) and that a change by hand left `INDEX.md` behind (`knowledge-index --check`), never blocking, finding the newest `knowledge-scan` in the plugin cache |
| `plan-next-batch` | `run-plan`'s scheduler: next runnable batch of a plan's `### Batch execution` table, `--check`, `--next`, `--outside`, `--exclude`, `--skip FX,FY` (batches set aside by the run — read as not done, never launched, nor their dependents; `--next` lists them as `held`), `--context`; `--parallel [N]` (default and cap 2): the batches of the current repo that may run at once — runnable, neither depending on the other, the paths their `## Cycles` blocks name disjoint (case folded), a sheet without a readable block kept apart — one JSON line `cap`, `batches`, `apart` (`batch`, `reason`); `run-plan` pairs its next batch with the second listed when `run.parallelBatches` is 2 |
| `sheet-cycles` | the `## Cycles` json block of a batch sheet: `--index` validates it (names, paths, one test project, 4 test / 8 production files per cycle, disjoint waves, `models` that exist, a block `closing` of `full` or `light`; exit 2 = no block) and prints the closing level the block plans and each cycle's code files, `--cycle ID --red\|--green` prints one cycle's contract (its `models` first), `--cycle ID --pending WORK` the files of its `ripple` and `toCreate` the batch has not changed (an `ALREADY_GREEN` that leaves any still gets its GREEN), `--done`/`--methods`/`--summary` read the cycle states for `pre-audit` and `audit-capture` |
| `run-question` | questions a running `run-lot`/`run-plan` asks, as lines of `run/.work.jsonl`: `ask`/`wait` (workflow side), `watch`/`pending`/`answer` (session side); kept, `run-lot` no longer writes them |
| `audit-round` | `open` / `close` around one audit fix round of `run-lot`: the files the fix changed, read off the tree against a snapshot (never its declared list), their diff, one `audit-round` line in `run/.work.jsonl` |
| `run-validate` | `apply <work>`: the user's answers to `## To validate` given in the mod — `reject`/`amend` written into `decisions` of the cycles named and as an `Hn` marked `user decision` of the sheet, the batch's relaunch command printed; run by `run-plan` and `run-lot` before any batch |
| `tdd-scope` | `restore <agent> <path>...` puts back what a TDD agent changed against its snapshot (the RED/GREEN check names the command); `evidence` prints the stubs seen carrying logic and, outside `run-lot`, the test files a GREEN changed; `red` is a `tdd-cycle` agent's RED checkpoint (report on stdin, the hook adds the agent id): the RED checks on the tree, the contract's methods, then the agent turns implementer |
| `closing-level` | `<sheet> <work> [--record]`: the run-lot closing of a batch, `full` or `light`, from its diff (`batch-baseline diff`, each file added, modified or deleted) and its `## Cycles` block (`lib/closing_level.py`: `closing` of `kit.config.json`, a forced `closing`); `--record` appends a `closing` line to the work file. One JSON line |
| `run-work` | the run work file `run/.work.jsonl`: `append`, `journal`, `drop`, `tmp` (temp folder for logs, never under `run/`), `purge` (every run: lines no run needs dropped, 3 runs kept) |
| `suites-plan` | `<work> FX [--lock]` (`--lock`: each run line under `cctoolkit build-lock --`, its command as words, for a batch run beside another): the global green of a run-lot batch resolved for a haiku agent to run — the build line and each suite `commands.suites` of `kit.config.json` requires for the batch diff, its `env` prefix, `commands.test`, the filter of a filtered suite (namespaces read off the production folders touched, matched against the first-level folders of its test project; none found → `unresolved`, a judgement left to the repair), output to a file of `run-work tmp`; records the dirty files under the test roots. `--tests-changed`: the files under the test roots written since, each marked `shared` under `layout.tests.shared` — what the run checks the repair's `testEdits` against. `--failed <output>`: the failed test names `tdd.failedTest` reads. One JSON object |
| `batch-baseline` | the files of one batch against `HEAD`, the files the user had already modified at batch start left out (a `preexisting` line of hashes in `run/.work.jsonl`, no content): `snapshot <work> FX`, `diff <work> FX [--code] [--name-only]`, `base <work> FX <path>`, `restore <work> FX [--save <patch>]` sets a blocked batch aside (with `--save`, its work kept under `refs/cctoolkit/aside/<plan folder>/FX`, created files included), `resume <work> FX` puts that work back three-way before `run-lot` resumes the batch from its saved cycles (a file that no longer merges: nothing written, the batch starts over), `commit <work> FX --sheet <sheet>` is the batch commit, the kit's only one, its message ending with the trailer `Kit-Batch: <plan folder>/FX` that tells `knowledge-scan` the change is already the plan's |
| `batch-worktree` | the worktree a batch runs in beside another (`run.parallelBatches` 2): `create FX --plan P --sheet S` (`<checkout>/.claude/worktrees/cctoolkit-batch-FX`, detached at HEAD, refused while the plan or the sheet differs from HEAD; the untracked kit files copied, `commands.worktreeSetup` run there; `.claude/worktrees/` git-ignored through `.git/info/exclude` when the repo does not ignore it), `land FX` (its commits rebased onto the checkout's HEAD, the checkout fast-forwarded; a conflict aborts the rebase and lists the paths), `undo FX --to SHA` (the checkout back before a landed batch whose build is red, local changes kept), `remove FX`, `prune` — one JSON line for `create` and `land`, exit 1 when refused |
| `build-lock` | `[--wait S] [--stale S] -- <command> [<arg>…]`: the command as words, never one quoted string (no `eval`: the Bash guards and the `rtk` rewrite read it), redirections outside the call; runs a long build or a whole suite under one lock per checkout — a `mkdir` lock in the git common dir, shared by every worktree (no `flock` under Git Bash) — keeping the command's exit; 75 after `--wait` (3600 s), a lock older than `--stale` (10800 s) taken over. For two batches of one checkout: their agent phases overlap, their long builds pass one at a time |
| `kit-diff <repo>` | a manual copy against the kit: MISSING / ADDED / DRIFT / MERGED, plus anonymisation alerts — the migration's first step |
| `learn-candidates` | the model-free half of `/learn`: the `## Audit gaps` of the `run-lot` reports (`todo/*/run/batches/FX.md`, kept after the transcripts are cleaned up), then the auditor sub-transcripts, a gap found in both counted once; reads French verdicts (`## Verdict — ECARTS`) |
